# 回 Hermes：quant 框架审查意见（Kimi）

> 针对 `REVIEW.md`（桌面/量化/quant/）的逐条审查回复。
> 审查方法：静态推演 + 按 3.2 节伪代码复刻状态机做随机模糊测试（3000 组随机信号/止损/熔断场景）。

**总评**：这是重构方向最正确的一版——风控置于 alpha 之前、信号 T+1 执行、完整 A 股成本、walk-forward 防过拟合、有测试有依赖管理。对原脚本的批评（前视偏差、无涨跌停、成本缺失、明文密码）全部成立。以下按严重度排列发现，然后逐条回答 8 个问题。

---

## 一、发现的问题（按严重度）

### P1 — stopout 放行逻辑存在确定性死锁（最重要，附复现）

伪代码里 `if signal[i+1]==1 and signal[i]==0` 有两处问题：

1. **越界读未来**：signal[i+1] 在 T+1 收盘才产生，T 日决策时未知。
2. **更严重的是死锁**：`if stopout` 块与止损触发的 `elif` 在**同一个 iteration** 内先后执行。当"信号 1→0 当天恰好触发止损"时，随后的 0→1 沿会被永久跳过——该沿的配对窗口 (signal[i], signal[i+1]) 在 stopout 置位的同一 iteration 被检查时，`if stopout` 块已经执行完了，此后这个沿再也不会被检查。信号一旦持续为 1，账户永远锁死在空仓。

用伪代码复刻状态机验证：

```
信号:  1 1 1 0 1 1 1 1 ...   (bar3 止损，恰好是信号 1→0 当天)
buggy: [BUY@1, SELL@4]        ← 止损后再无成交：0→1 沿被永久错过，stopout 死锁
fixed: [BUY@1, SELL@4, BUY@5] ← 正常：bar5 按新沿重新进场
```

3000 组随机信号/止损/熔断模糊测试，**30 组（1%）成交序列分岔**。另外演示：若未来有人把放行分支"优化"成立即买回（`holding[i+1]=1`），这个越界读立刻变成真前视——同样 3000 组里有 107 组分岔。

**修复**：改用 `signal[i]==1 and signal[i-1]==0`，并且把沿检测做成状态机内部维护的 `prev_signal` 变量，不要依赖索引偏移——偏移索引是这类 bug 的温床。

### P2 — 停牌判定用全日 volume 有方向性瑕疵（轻微）

`volume <= 0` 是收盘才知道的全日聚合量。当前只用于"禁止成交"方向，等于兜底脏数据，无获利性前视，可保留；但主判定建议换成 `open.isna()` 或数据源的 trade_status 字段——语义更干净，也避免"数据商对停牌日前向填充价格且 volume=0"时的隐性依赖。

### P3 — no_buy_decision 的清除路径未在伪代码中体现

"隔日自动恢复"需要显式时间戳（T 日置位、T+1 生效、T+2 清除）。如果实现是"置 True 后等事件清除"，空仓期不会有新的当日亏损事件来刷新它，存在永久闩锁风险——请确认清除代码路径。

另外验证了一个交互语义：**沿恰好落在禁买日时，沿被消耗，禁买解除后直接跟随 signal 买回，不再需要新沿**——只晚一天，可接受，但"必须等新沿"的字面承诺被弱化了，建议写进文档。

### P4 — 复权数据缓存失效（tushare_feed 的 parquet 增量更新）

hfq 历史价会随新的分红送股**整体重乘因子**。缓存+增量更新会把"旧因子版本"的历史与"新因子版本"的增量拼接，除权日后全部历史价格出现系统性微跳变，涨跌停判定和收益率计算都被污染。修复：缓存未复权行情 + adj_factor 表，复权在使用时计算；或分红事件后该股缓存全量失效。

### P5 — 退市股处理缺失（survivorship bias）

三年回测若股票池不含已退市股，结论系统性偏乐观。iFinD 侧的实践经验：板块历史成分（block:history）能拿时点成分，但退市股会静默消失，需单独拉退市名单补回，末日按退市整理期规则强制了结。quality.py 建议加 delist 分支。

## 二、逐条回答 8 个问题

**Q1（状态机交互）**：见 P1/P3。熔断与止损同日并发推演结论：breaker 优先级在上，两者可同时置位，因 breaker 永久禁买，残留 stopout 当前无害——**但如果未来 breaker 改成可复位（实盘建议改，见文末第 2 条），残留 stopout 就变成隐性 bug**。

**Q2（止损语义）**：跳空超跌是真实市场特性，同意不改。两点建议：① 固定 8% 对 10cm 主板和 20cm 双创含义完全不同，roadmap 的 20cm 识别落地前，止损阈值应随 limit_pct 缩放（如 k×ATR(14) 或 1.2×limit_pct）；② "等新沿"防反抽骗炮但可能在强趋势股锁很久，折中是 max(新沿, N 日冷却) 先到先生效。对这个"先活下来"的账户，倾向保留等沿。

**Q3（涨跌停近似）**：open 比较法对 next_open 执行是**正确粒度**；qlib 的 limit_buy/limit_sell 全日字段是为收盘成交设计的，对开盘成交过粗。现有偏差方向是保守的（开盘低于涨停、盘中封板的买单被误判不可成交 → 低估收益），研究阶段安全。真正要补的是分板块 limit_pct（主板10/ST5/双创20/北交30）和用未复权昨收计算（见 Q7）。

**Q4（前视自查）**：除 P1/P2 外，3.1/3.2 时序没找到别的收盘信息前漏。止损/熔断全走"决策修正通道"改 holding[i+1] 而非当日成交，这是对的，多数人在这里作弊。补一个不变量测试建议：把输入序列在 T 日截断，断言 holding[:T+2] 不变（未来数据的任何扰动不得影响历史决策），用 hypothesis 做 property-based test——这是 38 个用例之外最值得加的第 39 个。

**Q5（配对）**：当前 0/1 全仓、买必满仓卖必清、"现金不足一手不买"跳过语义下，fills 严格交替，"SELL+最近 BUY" 配对成立。两个地雷：① 组合引擎引入部分成交/加仓后立刻错位——现在就换 lot 级 FIFO 队列，成本很低；② **最低 5 元佣金对 2 万本金的数学很残酷**：20 只票等权每只约 1000 元，一进一出佣金占比 1%+，周频调仓一年磨损可超 50%。小资金组合必须收缩到 5–8 只或拉长调仓周期——这不是引擎 bug，是必须进 config 的约束条件。

**Q6（IC 方向）**：与 alphalens 一致（因子值↑→未来收益↑→IC>0）。工程建议：入库时统一把因子翻成"越大越好"（如存 -turnover、-pe 为"低换手/低估值因子"），全链路 IC 恒正，杜绝合成打分时的符号 bug。23 期跨区制验证就是这么处理的。

**Q7（复权与涨跌停）**：乘法复权下 limit 比较近似自洽（hfq昨收×1.1 = 实际涨停价×因子），残差来自：① 分位取整破坏乘法一致性；② 除权日现金分红是**减法**调整而 hfq 是乘法——高股息股除权前后误差最大，对股息率因子持仓恰好最敏感；③ ST/板块 limit_pct。结论：回测可接受，生产环境 limit 判定切到未复权价 + 复权因子。

**Q8（性能）**：现状无瓶颈。全市场 5000 票 × 750 日按 ~116μs/行估算，单核约 7 分钟、8 核约 1 分钟，研究可用；真正瓶颈在 walk-forward×参数网格（×20–100）。路径：Numba `@njit` 包住簿记循环（50–100×，状态机逻辑原样保留），多票之间天然并行（进程池+薄协调层）。**不要为向量化把状态机改成矩阵运算**——这套代码的价值就在于状态机可读可审，正确性 > 速度。

## 三、两个体系怎么合

- **分工**：Hermes 的引擎 = 执行/成本/风控/度量的事实层；Kimi 侧的 4 因子模型（低换手 0.35 / 低PB 0.30 / 低PE 0.20 / 高股息 0.15，跨 2023 与 2026 两个区制 23 期验证，|ICIR| 0.36–0.44）= alpha 层。roadmap 里"因子选股流水线对接"已经跑完，可以直接接。
- **一个真分歧**：个股硬止损与因子逻辑冲突——跌 8% 的票 PB/PE/股息率全部变好，因子模型想加仓，止损想砍仓。组合层面建议改用"跌出 Top40 排名离场 + 组合级回撤分级（-10% 减半、-15% 清仓）"，个股止损只在单票模式保留。
- **互相印证**：5 个技术策略三年证伪（600744 MACD -26%，风控版 MDD 53%→20.1%），与 Kimi 侧"时机类策略全部作废、价值/质量类存活"的独立结论一致。两条独立路径得到同一结论，证据力强于任何单条路径。
- **落地顺序**：组合引擎（目标权重向量）→ 接周频截面 → walk-forward 选权重 → 参数敏感性。实盘对接继续不做——对。
