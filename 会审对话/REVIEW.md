## 三、核心设计（重点审查对象）

### 3.1 回测时序模型（engine.py）

```
T 日收盘:  策略基于 <=T 的数据产生 signal[T]（0/1 目标持仓）
T+1 日:    按 execution 模式成交（默认 next_open = 次日开盘价）
T+1 收盘:  用 close 计市值 → equity
```

- 信号 shift(1) 实现 T+1，杜绝"当日信号当日成交"的前视偏差。
- **涨跌停**：`compute_limit_prices` 基于前收×±limit_pct 计算；`open >= limit_up` 视为涨停买不进，`open <= limit_down` 视为跌停卖不出；受阻交易不改变持仓，**次日继续尝试**（迭代修正，最多 20 次收敛）。
- **停牌**：`volume <= 0` 禁止买卖。
- **整手**：买入股数向下取整到 100 股；现金不足一手不买；卖出可零股（A股规则）。
- **成本**：买入=佣金(rate,min5)+过户费+滑点；卖出=佣金+印花税+过户费+滑点。

### 3.2 风控状态机（engine.py 资金簿记循环内，重点审查）

5 道防线全部**收盘后判定、次日生效**（无前视），状态变量：

| 状态 | 语义 |
|---|---|
| `peak_price` | 持仓期最高价（含买入当日 high），卖出重置为 0 |
| `stopout` | 止损/止盈离场标记：**离场后必须等到原始信号出现 0→1 沿才允许重新进场**（防止"信号一直为1 → 止损后立刻买回 → 再止损"死循环） |
| `breaker_triggered` | 回撤熔断：触发即清仓，**永久**禁止再产生买入决策（holding 全部压 0） |
| `no_buy_decision` | 当日亏损熔断：当日触发 → 次日禁止空仓时产生买入决策，**隔日自动恢复** |

关键实现（伪代码）：

```python
for i, (date, row) in enumerate(df.iterrows()):
    # ① 决策修正层：影响 holding[i+1]（明日执行）
    if breaker_triggered:            holding[i+1] = 0
    elif no_buy_decision and 空仓:    holding[i+1] = 0
    if stopout:
        if signal[i+1]==1 and signal[i]==0:  stopout = False   # 新信号，放行
        else:                                 holding[i+1] = 0
    elif 持仓中 and close <= 成本×(1-stop_loss):   holding[i+1]=0; stopout=True
    elif 持仓中 and close <= peak×(1-trail):      holding[i+1]=0; stopout=True

    # ② 执行层：按 holding[i]（昨日决策）成交
    # ③ 收盘后：更新熔断状态（drawdown/daily_loss）→ 作用于明日决策
```

**设计要点**：止损/止盈/熔断全部走"决策修正通道"（改 holding[i+1]），而不是改当日执行（当日 close 判断、当日 open 成交 = 前视偏差）。止损触发价用买入价（open+滑点），触发后卖出价含滑点，实际亏损可能因跳空深于 8%——这是真实市场特性，不是 bug。

### 3.3 绩效指标（metrics.py）

`compute_metrics()` 输出：总收益/年化/年化波动/夏普/索提诺/卡玛/最大回撤/最长回撤持续/偏度/峰度/年化换手/胜率/盈亏比/平均单笔盈亏/交易数/alpha/beta/信息比率。

- 回撤定义为**正数幅度**（0.2 = 回撤 20%）。
- 夏普在年化波动 < 1e-10 时返回 0（浮点噪声保护）。

### 3.4 因子模块（factors/）

- `winsorize`：MAD 法（中位数±3×1.4826×MAD）或分位数法。
- `neutralize`：因子对行业哑变量 + ln(市值) 回归取残差（numpy lstsq，无 statsmodels 依赖）。
- `rank_ic`：逐期 Spearman 相关；`ic_summary` 给出 mean_ic/ICIR/t 值/正占比；`quantile_analysis` 分层检验 + 多空组合收益。

### 3.5 walk-forward（research/walk_forward.py）

时间轴切 K 窗，每窗前 train_ratio 选参（按夏普）、后段样本外测试，拼接纯样本外净值。**样本外业绩才是可发布业绩**。

## 四、真实回测结果（600744.SH，MACD，2023-01~2026-07，2 万本金）

| 指标 | 无风控 | 止损8%+仓位80%+回撤熔断15% |
|---|---|---|
| 总收益 | -26.0% | -20.1% |
| 最大回撤 | **53.2%** | **20.1%** |
| 交易次数 | 35 | 6 |
| 胜率 | 25.7% | —（止损后未再进场） |

**解读**：风控不能让亏钱策略变赚钱（策略本身无效，MACD 在此票三年负收益），但能把灾难性回撤压成可控回撤。这 5 个策略已证伪，后续研究重心转向因子选股 + 组合。

## 五、请 Kimi 重点审查的问题清单

1. **风控状态机**：`stopout` 的 0→1 沿判定、熔断与止损并发时的交互（如回撤熔断触发当天恰好止损触发）、`no_buy_decision` 与 `stopout` 同时为真的情况——有无逻辑漏洞？
2. **止损语义**：止损触发价用 open+滑点作为成本，跳空导致的超跌是否在可接受范围？是否需要"止损后冷却期"（当前是等新信号）？
3. **涨跌停近似**：用 `open >= limit_up` 判断"一字涨停买不进"是否过于保守/乐观？qlib 用的是数据层 limit_buy/limit_sell 字段（日线为"日内全部受限"语义），哪种更合理？
4. **前视偏差**：请从 3.1/3.2 的时序里找任何"用当日收盘信息影响当日或更早决策"的漏洞。
5. **胜率/盈亏比配对**：全仓 0/1 模型下 pnl 配对（SELL.net + 最近 BUY.net）是否永远正确？部分成交、连续买卖时有无错位？
6. **因子方向**：`quant/factors/` 的 IC 判定方向约定（因子值越大未来收益越高 → IC>0 有效）是否与主流（alphalens）一致？
7. **数据质量**：复权（hfq）数据下涨跌停价按复权前收计算，除权日附近误差是否可接受？
8. **性能**：资金簿记循环逐日 Python 循环（~860 行数据 <0.1s），但未来全市场组合回测是否瓶颈？有无更好的向量化方案？

## 七、会审公理（方法论附录，2026-08 固化）

双 AI 会审（Hermes ↔ Kimi）历经三轮互审后沉淀的方法论公理，后续所有研究与代码改动须遵守：

1. **IC 正 ≠ 组合有效**（三次应验：低换手 2025-26、E/P+低PS 槽位、反转因子复合）——因子截面排序有效不代表 Top-N 集中组合赚钱。验证必须走到组合回测 + walk-forward，不能停在因子 IC。
2. **加因子不一定加分，加相关因子是减分**（五因子 vs 三因子轮次）——相关矩阵是因子入库的前置检查。
3. **"冗余"在因子研究是减分，在组合构建是容错**（K3 P7 重审）——同一因子的两种评价视角可以相反。
4. **任何指标口径必须参数化并声明**（P6 年化口径：周频 equity 走 252 会放大 4.85×）——报告必须声明年化频率、基准口径（买入持有等权 vs 周频等权差 24pt）。
5. **停牌语义三原则**（P7）：计值用 ffill、执行保持 NaN 跳过、调仓目标维持当前持仓——停牌不可成交，恢复后不追错卖。
6. **所有结论须可复现**：Kimi 侧每次核验都独立复跑，数字逐位一致才算通过；任何一方推翻自己的结论必须主动申报（P7 案例）。
7. **样本外纪律**：阈值/权重不得全样本调参（D 方案：2023 训练 → 2024-26 验证）。
8. **walk-forward 是加仓前唯一硬门**：样本内再好看，近期样本外为负 = 不加仓（2025-26 双版本均负，立场不变）。
